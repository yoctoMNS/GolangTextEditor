# GolangTextEditor 絶対遵守ルール

このスキルは `CLAUDE.md` の方針を、**例外を認めない具体的なチェックリスト**として
運用するためのものである。CLAUDE.md が「なぜ」を説明するのに対し、ここは
「何を確認すれば完了と言えるか」を定義する。

## 絶対禁止事項 (MUST NOT)

1. `internal/buffer` と `internal/editor` から、描画・ウィンドウ・入力系ライブラリ
   （`ebiten`, `go-sdl2`, `raylib-go`, `go-gl`, その他GUI/グラフィックスライブラリ）を
   importしては **絶対にならない**。これらのパッケージは `go test` がディスプレイ無し
   環境で通ることが必須条件。
2. バッファ全体（`Buffer.lines` 全体）をキー入力1回ごとにコピー・再構築する実装を
   **絶対に書かない**（例: 毎回 `strings.Join` して丸ごと作り直し、それをまた
   `strings.Split` し直す、等）。編集は該当行・該当範囲に閉じた操作にすること。
3. 新規パッケージ・新規公開関数を、対応するテスト無しでコミットしては **絶対にならない**
   （`internal/app` 配下の描画/入力バックエンド実装コードを除く。理由は下記チェックリスト参照）。
4. `gofmt` を通していないコード、`go vet ./...` が失敗する状態のコードを
   コミットしては **絶対にならない**。
5. このフェーズ（基本テキストエディタ）で要求されていない機能
   （マルチタブ、プラグイン機構、ゲームスクリプト実行、シンタックスハイライト、
   ネットワーク機能等）を **依頼されていないのに先回りして実装しない**。
6. Windows/Linux のどちらかでしかビルドできないコード（GOOS特有APIの直接叩き等）を、
   `//go:build` タグでの分岐無しに共通コード (`internal/buffer`, `internal/editor`) に
   混入させては **絶対にならない**。

## 作業完了前チェックリスト (MUST)

このリポジトリでコードを変更したら、完了報告の前に **必ず全項目を実行し、
結果を確認すること**。一つでも失敗した状態で「完了」と報告してはならない。

- [ ] `gofmt -l .` の出力が空であること（フォーマット崩れが無いこと）
- [ ] `go vet ./...` が警告・エラー無しで終了すること
- [ ] `go test ./...` が全て `ok` で終了すること
- [ ] `go build ./...` (Linux, 現在の環境) が成功すること
- [ ] `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./...` が成功すること
      （Windows向けクロスコンパイル確認。CGOに依存する変更を入れた場合はここで検出される）
- [ ] `internal/buffer`, `internal/editor` の変更に対して、対応するテスト
      (`*_test.go`) を追加・更新したこと
- [ ] `internal/app`（ebiten依存の描画/入力層）を変更した場合は、可能であれば
      Xvfb等の仮想ディスプレイ上で実バイナリを起動し、クラッシュしないことを
      確認したこと。表示内容の目視確認ができない環境では、その旨を報告に明記すること
      （「動作確認済み」と虚偽の報告をしない）

## 設計判断に迷ったときの優先順位

1. **正しく動くこと** > 2. **軽量・高速であること** > 3. **将来の拡張性**

将来の拡張性のために今の実装を複雑にする判断は、明確な指示が無い限り取らない。
複雑にする前に、まず CLAUDE.md の「過剰設計の禁止」を読み返すこと。
